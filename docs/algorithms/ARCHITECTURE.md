هذا هيكل مستهدف وليس ادعاءً بأن جميع المجلدات أو المحركات موجودة حالياً. يجب فحص ملفات المستودع وطلبات الدمج المفتوحة قبل إنشاء وحدات مكررة.

## 2. تدفق فحص المحتوى

1. استقبال الطلب في الخادم والتحقق من هوية المستخدم وصلاحياته وحدود المعدل.
2. تحديد نوع المحتوى وسياقه ووجهة النشر.
3. الاحتفاظ بالنص الأصلي كما أُرسل، وإنشاء نسخة تحليل مطبّعة مستقلة.
4. فحص القواعد والأنماط والقواميس، بما فيها صيغ التحايل الإملائي والعربية وArabizi والخلط بين اللغات.
5. تحليل السياق: اقتباس، شرح لغوي، توثيق، بلاغ، إساءة موجهة، تهديد، أو خطاب كراهية.
6. حساب إشارات المخاطر مع إرجاع أسباب قابلة للتفسير وإصدار المحرك.
7. تطبيق سياسة القرار الخاصة بنوع المحتوى.
8. تسجيل الحد الأدنى اللازم من بيانات القرار، ثم السماح أو طلب المراجعة أو الرفض.
9. إعادة الفحص عند التعديل، وعدم اعتبار فحص النسخة السابقة صالحاً للنص الجديد.

## 3. قرارات البوابة

- `allow`: لا توجد إشارة تستدعي تدخلاً وفق السياسة الحالية.
- `allow_with_context`: محتوى حساس مسموح به لسياق لغوي أو تعليمي أو توثيقي مشروع، مع ضوابط عرض عند الحاجة.
- `review`: ثقة غير كافية أو إشارات متعارضة؛ يحال إلى مراجعة بشرية ولا يصنف تلقائياً كإدانة.
- `block`: مخالفة واضحة لسياسة النشر.
- `urgent_escalation`: تهديد موثوق أو خطر شديد يستلزم مسار إشراف عاجلاً وفق سياسة المنصة.

يجب ألا تكون درجة المخاطر وحدها سبباً للعقوبة. القرار يعتمد على نوع المحتوى والسياق والثقة وشدة الضرر.

## 4. نقاط الإدخال المطلوب حصرها وربطها

- التسجيل: اسم المستخدم، الاسم الظاهر، النبذة.
- المعجم: الكلمة، المعنى، الترجمة، الأمثلة، الوسوم والملاحظات.
- المساهمات: الإضافة والتعديل والاقتراحات.
- المراجعة والتحكيم: ملاحظات المحررين وردودهم.
- التعليقات والردود والمناقشات.
- الرسائل الخاصة والمجموعات: لا تدخل التدريب افتراضياً، ويجب تحديد سياسة فحص وخصوصية معلنة قبل أي معالجة آلية تتجاوز الحماية الضرورية.
- البلاغات: يجب السماح بتقديم النص المسيء كدليل دون معاقبة المبلّغ لمجرد اقتباسه.
- أدوات الإدارة: تخضع لتسجيل تدقيق وصلاحيات، ولا توجد تجاوزات صامتة.

يُنشأ سجل تكامل يحدد لكل نقطة: واجهة API، الخدمة الخادمية، جدول التخزين، مسار الإنشاء والتعديل، الصلاحيات، والاختبارات. لا تُعتبر النقطة محمية حتى يثبت اختبار أن مسارات الكتابة البديلة لا تتجاوز البوابة.

## 5. حدود الثقة والأمن

- العميل غير موثوق؛ يمكن تجاوز أي تحقق في الواجهة.
- النص المرسل غير موثوق، وكذلك اقتراحات القواميس والتصنيفات.
- لا تحفظ مفاتيح أو أسرار النماذج في المتصفح.
- لا تمنح محركات التحليل صلاحيات قاعدة البيانات أو النشر.
- لا تسمح للمحرك بقبول أو رفض مساهمة معجمية نهائياً.
- صلاحيات الإدارة والمحررين تُطبق في الخادم وقاعدة البيانات، لا بمجرد إخفاء الأزرار.
- يجب حماية سجلات التدقيق من التعديل غير المصرح به، وتقليل النصوص الحساسة المخزنة.
- لا تغييرات على Supabase schema أو RLS أو بيانات الإنتاج ضمن مرحلة التوثيق هذه.

## 6. واجهة نتيجة موحدة مقترحة

ينبغي أن تكون نتيجة المحرك ذات مخطط ثابت ومُصدّر بإصدار:

- `decision`: أحد القرارات المحددة أعلاه.
- `risk_level`: تصنيف منخفض/متوسط/مرتفع/حرج.
- `score`: درجة رقمية اختيارية ومُعايرة، لا تُعرض كاحتمال حقيقة دون معايرة.
- `signals`: رموز أسباب قابلة للتفسير، لا قوائم ألفاظ مسيئة مكشوفة.
- `context`: نوع السياق الذي تم التعرف عليه مع مستوى الثقة.
- `engine_version` و`policy_version`.
- `requires_human_review`.
- `processed_at`.

يجب اعتماد TypeScript schema واختبارات contract قبل ربط واجهات المنصة.

## 7. الخصوصية والاحتفاظ

- اجمع أقل قدر ممكن من البيانات اللازمة للحماية والتدقيق.
- افصل سجلات الإشراف عن بيانات التدريب.
- احذف أو أخفِ الهوية من أمثلة التدريب، مع مراجعة خطر إعادة التعرف.
- لا تستخدم الرسائل الخاصة أو محتوى المستخدمين الحساس في التدريب افتراضياً.
- حدد مدد الاحتفاظ والوصول والحذف في سياسة الخصوصية قبل الإطلاق.
