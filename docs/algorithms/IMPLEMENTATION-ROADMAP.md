## سجل طلبات الدمج السابقة

حالة الطلبات عند إعداد هذه الوثيقة:
- **#20**: محرك Darija مستقل، مفتوح وغير draft.
- **#21**: محرك Darija مستقل بمسارات متداخلة، مفتوح وdraft.
- **#23**: محاولة تجميع #20 و#21، مفتوحة وdraft، وتحتوي مسارات مشتركة.
- **#24**: benchmark وتقرير، مفتوح وdraft، ويستهدف فرع #23 لا main.

هذه الطلبات ليست أربعة تغييرات مستقلة قابلة للدمج المتتابع. #23 هو مسار التجميع، و#24 يعتمد عليه. يجب فحص الاختلافات والاختبارات والتاريخ قبل تقرير ما يعاد استخدامه. لا تدمجها آلياً ولا تغير قواعدها أو تغلقها دون مراجعة منفصلة.

## أولويات التنفيذ الحالية

1. اعتماد هذه الوثائق كأساس تصميم.
2. مراجعة #20/#21/#23/#24 وتحديد المصدر الأفضل لكل وحدة.
3. توحيد محرك الدارجة مع benchmark أكثر تمثيلاً.
4. بناء محرك سلامة المحتوى أولاً كخدمة مستقلة مع اختبارات سياقية.
5. إنشاء خط feedback وreview محكوم، دون تدريب تلقائي مباشر.
6. بناء بوابة الخادم وعقدها واختبارها قبل توصيلها بجداول الإنتاج.
7. ربط نقاط إدخال المحتوى واحدة تلو الأخرى.
8. تفعيل المراقبة والإطلاق التدريجي بعد موافقة مستقلة.

## ضوابط التغيير

- كل مرحلة في PR مستقل.
- لا دمج دون موافقة المستخدم.
- لا تعديل Supabase production أو RLS أو بيانات الإنتاج ضمن أعمال التوثيق أو دون مراجعة صريحة.
- لا تغيير تصميم الموقع أو واجهاته الحالية إلا إذا تطلب التكامل ذلك وجرى الاتفاق عليه.
- لا نشر أو تفعيل حماية على الإنتاج قبل اختبارات التكامل والمراجعة.
- يجب توثيق نتائج CI الفعلية، وعدم وصف الاختبارات بأنها ناجحة قبل التحقق.

## معايير القبول العامة

- تغطية موثقة لكل نقطة إدخال.
- حماية خادمية لا يمكن تجاوزها عبر عميل بديل.
- تفسير قرار الفحص وإصدار المحرك والسياسة.
- حماية الاستخدام اللغوي المشروع من الحظر الآلي غير المبرر.
- فصل اقتراحات المستخدم عن البيانات المعتمدة.
- مصدر وحقوق موثقة لمجموعات البيانات.
- benchmark ممثل مع نتائج لكل فئة.
- آلية rollback واختبارات أمن وخصوصية.
